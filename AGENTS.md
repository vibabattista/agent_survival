# Tiny Town: project guidance

- Tiny Town is a local simulation lab for observing AI agents pursuing distinct goals in a shared, persistent world. The human is the experiment operator; intervention is secondary to observation.
- Keep the application and data local. The user explicitly requested the optional OpenAI provider; use it only when selected. Do not add other remote APIs, telemetry, CDN assets or cloud inference without the user's explicit request.
- Keep models replaceable at runtime. The adapters support a locally running Ollama server and the optional OpenAI API; provider and model names are configured in the lab. Do not hard-code assumptions about a particular model into simulation rules.
- The world enforces actions and consequences; agents choose actions using the configured model. Do not present scripted output as model-generated or agent self-reports as hidden reasoning.
- Preserve inspectable event logs, editable goals and world conditions, durable local experiment storage and export when changing the simulation. Undo/redo and reflection retry were removed at the user's request. Explain limitations and data-loss implications.
- A day contains 24 ticks. Agent decisions and daily chronicles should be generated by models, not canned dialogue.
- Start with `python3 server.py` and open `http://127.0.0.1:8765/lab.html`. Ollama must be running separately for local models. For OpenAI, supply the key through the server's environment as described in README.md.
- Never put credentials in source files, logs or browser state. Preserve existing user changes and verify changes appropriately.

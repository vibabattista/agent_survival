# Tiny Town

Local simulation prototype. The server stores experiments on this computer in `data/tiny_town.sqlite3`; use Export experiment to save a JSON copy or Import experiment to restore one. Select Ollama for local models, or OpenAI for paid API models. Selecting OpenAI sends prompts and simulation context to OpenAI and uses API credits.

To use OpenAI, open Terminal and run these commands (the `read` command hides your key as you paste it):

```sh
cd /Users/viba/Documents/ChatGPT/tiny_town
read -rs 'OPENAI_API_KEY?Paste your OpenAI API key: '
export OPENAI_API_KEY
python3 server.py
```

Keep that Terminal window open and visit http://127.0.0.1:8765/lab.html. A fresh browser state defaults to OpenAI, `gpt-6-luna`, and reasoning effort `none`. Existing saved experiments keep their settings, including when using New experiment; to change them, select the provider, model and effort under Environment and click Apply settings. Restart the server in the same terminal if it was already running without the key. Never paste the key into the app, code or chat. The key is stored only in the process environment, not the experiment; close the terminal to discard it. With Ollama selected, an API key is not required and requests go to your local Ollama service.

Each tick sends one decision request per living agent who is not travelling. Conversation, conflict, defence, history lookups and notebook reorganisation add requests. At the end of a day, each survivor gets a private reflection request, and there is also a separate chronicle request. A single conversation can use up to twice `dialogueRounds` additional model requests; the default is six. OpenAI requests are billed even if a tick fails; the app does not enforce a spending limit. Start with one tick and check your API usage.

## Current scenario

Shelter and woods, 12 day and 12 night ticks. Agents each choose an action using a frozen start-of-tick snapshot. The world applies effects after all choices are collected. The balanced default is food loss 5 per tick, apple food 25, rest energy 15 and rest health 5. The other hazards remain editable. At night there is one configured chance of a shadow attack per tick; if it occurs, one living person outside (including travellers) is chosen at random. An agent who arrives at shelter is safe that tick. Existing experiments retain their rules; the Load balanced values button prepares the suggested values and Apply settings confirms them. Agents can carry at most six apples; excess found apples fall on the ground. Existing saved inventories aren't silently truncated.

Agents can take/store apples, give one apple to a nearby agent, attempt to take one from a nearby living person or body, speak, attack, rest, search, travel and eat. A living target may allow, refuse or fight; after refusal the taker may back off or fight. Fighting does not automatically transfer an apple. An attack uses chosen energy; the defender chooses energy to block and the difference becomes damage. Food disputes allow up to the configurable number of dialogue rounds; if agents still cannot agree, food remains in storage. Agents see qualitative descriptions of their own needs, not the numbers. They receive their inventory, local people, visible bodies, local resources, a list of available actions and their legal targets. OpenAI's action schema and the world both reject unavailable choices. Speech is delivered only locally; an agent choosing to depart that tick cannot hear a conversation.

Agent requests contain separate SENSES, INTERNAL and ACTIONS sections, including in conversations and defence. Action descriptions explain the interface; the simulation applies and validates world changes. New agents start with the goal Survive and no extra personal instructions. Existing goals and custom personal instructions are preserved.

Each agent receives its ordered experiences from the current day, encoded compactly as [tick, kind, text]; spoken words remain verbatim. The agent and operator can edit the private notebook. The notebook is not included on every call: agents can choose to search it or their own earlier experiences, including old conversations and daily reflections. Searches use exact phrase matching, with pages of up to ten results. Matching prior speech also returns other speech the same agent heard that tick, not another agent’s private record. The search limit `maxRecallSearches` is per agent per tick (default 3); the agent chooses searches before continuing its action, and each search adds another model request. The original histories are retained on disk and in export. Old untimed journal entries are searchable with their provenance marked unknown.

Agents can append to or rewrite their notebook during a model response. A surviving agent is asked to write a reflection and update the notebook at the end of the day; it chooses the content and organisation. If the notebook exceeds `maxNotebookChars` (default 24,000), the agent is asked to shorten it before its next response; this adds a model request. If reorganisation fails, the previous saved notebook is preserved and the error is shown. The agent can choose a `think` action that consumes its tick. Personal stated thoughts are generated text, not hidden reasoning. Existing daily reflections remain preserved; when an older agent has no notebook, they form its initial searchable notebook. The operator can edit this notebook in Agents & harnesses.

The Conversations & thoughts panel groups decisions, full spoken messages and events by tick, with day and agent filters. Scroll inside the panel or select a card to follow its recorded map state, full speech bubbles and stat changes; Return to live restores the current view. Visual state recording starts with new ticks after this update: older events without recorded states are marked unavailable, rather than reconstructed. State snapshots are stored only when the visible state changes, plus the end of each tick. The tick log and raw request records remain available. The model request log records history lookups and results for inspection.

Free-form model speech can still invent details. The tick log flags some possible unsupported anatomy, medical actions, shelter searches and remote communication using keyword checks; these warnings can miss cases and can also flag legitimate hypothetical statements. They don't prevent deception and don't prove a statement false. The prompt and raw outputs are available in the request log. The daily chronicle can also be inaccurate; consult the underlying event log.

Assisted travel requires both agents at the same location and the person being helped to accept. It takes four ticks by default. The person being helped spends up to 20 energy; the helper spends 20 plus any shortfall. Acceptance replaces the recipient's planned action for that tick. If multiple offers overlap, they are rejected rather than assigning priority by agent order. Existing saved simulations retain their travel settings; use Load travel values, then Apply settings to set running to one tick, walking to two and assistance to four. Those values are editable. Agents already travelling cannot offer or accept help, and if a helper dies in transit their companion currently continues alone.

The chronicle receives the committed action log and agent-stated thoughts from new ticks. These statements are not hidden reasoning and the chronicle may still make mistakes; compare it to the event log and raw outputs. A failed reflection is logged and the simulation can continue; no automatic paid retry is made. A failed chronicle is logged separately.

## Prototype limits

Only the initial decision phase uses a shared snapshot; some other simultaneous actions are still resolved sequentially. Agents negotiate competing claims for storage, ground items or the same person's possessions; they can yield, insist or attack. If the contest remains unresolved at the configured limit, the items stay put. Conversations can continue, end or turn into an attack; the existing `dialogueRounds` setting bounds the number of back-and-forths. Two agents' attacks and defences are applied together, including when both attacks are lethal. Overlapping group attacks against one defender, or multiple attacks by one person, are not resolved and are logged; no group combat allocation rule is implemented. Other interactions are not fully simultaneous. Agents cannot yet edit individual starting stats in the interface. Names, goals, personality, personal memory and per-agent instructions are editable; historical events and private reflections remain read-only. Locations and action types are fixed; settings edit numerical rules only. Model-generated memories and dialogue may be inaccurate or invented. Older saved memories may already contain information from elsewhere; they are not silently changed. Model output is not guaranteed valid. If a response repeats identical JSON objects with extra text, the app uses the matching object and records a warning; conflicting or invalid responses abort the tick. The original response remains in the raw request log. This is not a research-grade or fully reproducible simulation.

Settings are editable as JSON in the environment section. Initial values apply when starting a new experiment; changes to existing agents' stats are not retroactive. Undo and retry controls are removed. Starting a new experiment archives the previous state and raw requests in the local database; exports include the archives. The current state is stored once, while events and each agent's experiences are appended as individual records. New observations are no longer written three times into separate personal lists. Old browser data and its history are retained on first migration; the browser copy is not deleted. Import experiment can restore a previously exported JSON file, including a raw response that was only in the browser's memory at export time. The request log shows the model's token usage when reported.

Old conversations are no longer included automatically in every prompt. A day’s full experiences, a long current conversation, user-entered personal memory, or retrieved pages can still make a prompt large; there is no fixed token ceiling or spending limit. Searches and notebook reorganisation can add billed model calls. The model context window and the server's 100,000-byte request limit can stop a request; nothing is silently truncated. Inspect each request's reported token usage in the raw log. Disk space is finite. Models and model downloads are managed through Ollama. See AGENTS.md for project guidance.

## Offline tests

Run `node --test tests/harness.test.js` and `python3 -m unittest discover -s tests` from this folder. They use mocked responses; they do not call models or spend API credits. They exercise local perception, available actions, remote speech, a departing agent, hidden hazards, ungrounded-output flags and the OpenAI action-schema boundary. Passing these tests does not establish that arbitrary LLM speech is truthful or that every simulation mechanic is correct.
